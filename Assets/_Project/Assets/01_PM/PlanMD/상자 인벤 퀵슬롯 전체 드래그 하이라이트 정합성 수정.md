# 상자/인벤/퀵슬롯 전체 드래그 하이라이트 정합성 수정

## Summary
- 적용 범위는 상자, 인벤토리, 퀵슬롯 전부다.
- 실패 스왑 하이라이트는 유지하되, 실제 스왑 대상이 있는 경우에만 표시한다.
- 없는 대상, 숨은 대상, 닫힌 상자 controller, stale model/view 불일치 때문에 엉뚱한 빨간 칸이 뜨는 경로를 막는다.

## Key Changes
- `GridInventoryController`의 전역 grid 하이라이트를 정리한다.
  - 인벤 ↔ 인벤, 상자 ↔ 상자, 인벤 ↔ 상자, 퀵슬롯 → 인벤/상자 모두 이 경로를 탄다.
  - `overlappingItems`에 잡힌 target item이 실제 `itemViews`에 존재하고 현재 view에 붙어 있을 때만 스왑 후보로 인정한다.
  - target item이 모델에는 있는데 view에 없으면 `RefreshView()` 후 재검증하고, 그래도 없으면 스왑 후보에서 제외한다.
- 실패 스왑 위치 표시는 실제 target item이 있을 때만 유지한다.
  - 실제 대상 있음: 기존처럼 실패 스왑 예상 위치를 빨간색으로 표시한다.
  - 실제 대상 없음: 현재 드래그 아이템 후보 칸만 표시하고, 멀리 떨어진 빨간 스왑 위치는 그리지 않는다.
- 퀵슬롯도 명시적으로 검증한다.
  - 퀵슬롯 → 퀵슬롯 같은 슬롯은 기존처럼 no-op/무하이라이트 유지.
  - 인벤/상자 → 퀵슬롯은 target quickslot item이 실제 슬롯에 있을 때만 swap 가능성 계산을 한다.
  - target quickslot이 비어 있으면 정상 초록, target item이 있고 source grid로 되돌릴 수 없으면 해당 퀵슬롯만 빨강으로 표시한다.
- 닫힌 상자/더미 인벤 controller가 남지 않게 한다.
  - `GridInventoryController.Dispose()`를 추가해 `activeControllers` 제거, 이벤트 구독 해제, slot color reset을 수행한다.
  - `LootController.CloseLoot()`와 `DetachPlayerInventory()`에서 dummy loot/player controller를 destroy 전에 dispose한다.
  - 퀵슬롯 드래그 중에도 stale 상자 controller가 하이라이트 계산에 끼어들지 않게 한다.

## Coverage Matrix
- 상자 내부 이동: 적용
- 인벤 내부 이동: 적용
- 상자 ↔ 인벤 이동: 적용
- 퀵슬롯 ↔ 퀵슬롯 이동: 적용
- 퀵슬롯 → 상자/인벤 이동: 적용
- 상자/인벤 → 퀵슬롯 이동: 적용

## Test Plan
- 빈칸 위 드래그에서 멀리 떨어진 빨간 칸이 뜨지 않는지 확인한다.
- 실제 다른 아이템 위 드래그에서는 실패 스왑 위치가 기존처럼 보이는지 확인한다.
- 상자를 닫았다 다시 열어도 이전 상자 하이라이트가 끼어들지 않는지 확인한다.
- 상자, 인벤, 퀵슬롯 각각 자체 이동과 상호 이동을 모두 확인한다.
- `dotnet build Assembly-CSharp.csproj`로 컴파일 오류가 없는지 확인한다.

## Assumptions
- 빨간 실패 스왑 미리보기는 실제 스왑 대상이 있을 때만 의미 있다.
- 모델에만 있고 화면에 없는 아이템은 드래그 하이라이트의 스왑 후보로 쓰면 안 된다.
