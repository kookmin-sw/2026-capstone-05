# 2라 이후 사망 아이템 드랍 누락 수정

## Summary
- 원인은 1라 종료 패널티에서 `PlayerRespawn.suppressNextDeathDrop`를 켜고, 실제 사망 리스폰 루틴을 거치지 않아 그 플래그가 2라 첫 사망까지 남는 흐름이다.
- 이 플래그가 2라 첫 사망 때 소비되면서 `DropInventoryAtDeathPosition()`이 스킵되어 호스트/클라이언트 모두 “죽었는데 아이템이 안 떨어지는” 증상이 난다.
- 라운드 종료 강제 귀환/패널티와 일반 사망 드랍 억제를 분리해, 다음 라운드 사망 드랍에 영향이 없게 한다.

## Key Changes
- `Assets/_Project/Scripts/06_Backend/Respawn/PlayerRespawn.cs`
  - `ApplyRoundEndBunkerPenaltyIfOutside()`에서 `suppressNextDeathDrop = true`를 더 이상 설정하지 않는다.
  - 라운드 종료 패널티는 기존처럼 벙커 밖 플레이어의 인벤토리/퀵슬롯을 드랍 없이 제거하고 장비만 해제한다.
  - `SpawnAtSpawner()` 진입 또는 완료 시 `suppressNextDeathDrop = false`를 명시적으로 초기화해 강제 스폰/라운드 전환 뒤 stale suppress 상태가 남지 않게 한다.
  - 일반 사망 루틴에서는 기존처럼 로컬 입력 권한 플레이어만 `GlobalDragDropRouter.DropAllPlayerItemsAt(deathPosition)`를 호출한다.

- 네트워크 드랍 흐름은 유지한다.
  - 호스트 플레이어 사망: 호스트 로컬 입력 권한 객체가 `RequestDropItem()`을 호출해 드랍 생성.
  - 클라이언트 플레이어 사망: 클라이언트 로컬 입력 권한 객체가 RPC로 StateAuthority에 요청하고, `RpcSpawnDroppedItem`으로 전체에 생성.
  - StateAuthority 쪽 원격 복제본은 중복 드랍을 만들지 않는다.

- 라운드 종료 패널티 의도는 유지한다.
  - 1라 5분 종료 시 벙커 밖 플레이어의 아이템은 바닥에 떨어뜨리지 않고 제거한다.
  - 다음 라운드에서 새로 획득한 아이템은 사망 시 정상 드랍된다.

## Test Plan
- `dotnet build Assembly-CSharp.csproj` 또는 Unity 컴파일 확인.
- 1라 종료 시 벙커 밖 플레이어 아이템이 기존처럼 드랍 없이 제거되는지 확인.
- 2라 시작 후 호스트가 아이템을 획득하고 사망하면 사망 위치에 아이템이 드랍되는지 확인.
- 2라 시작 후 클라이언트가 아이템을 획득하고 사망하면 호스트/클라이언트 양쪽에서 드랍 아이템이 보이는지 확인.
- 2라 첫 사망뿐 아니라 이후 반복 사망에서도 아이템 드랍이 계속 정상인지 확인.
- 라운드 종료 강제 스폰, 일반 사망 리스폰, 벙커 재진입 제한 흐름이 서로 간섭하지 않는지 확인.

## Assumptions
- 라운드 종료 패널티는 “아이템을 드랍하지 않고 제거”하는 현재 설계를 유지한다.
- 사망 아이템 드랍은 각 플레이어의 로컬 입력 권한 객체에서만 시작하는 현재 네트워크 구조가 맞다.
- 이번 수정 범위는 stale death-drop suppression 제거이며, 인벤토리/루팅 저장 구조나 드랍 RPC 구조는 바꾸지 않는다.
