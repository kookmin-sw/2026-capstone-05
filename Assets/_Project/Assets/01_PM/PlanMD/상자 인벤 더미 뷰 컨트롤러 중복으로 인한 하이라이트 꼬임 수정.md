# 상자 인벤 더미 뷰/컨트롤러 중복으로 인한 하이라이트 꼬임 수정

## Summary
- 확인 결과 상자는 기존 `GridInventoryView` 자체를 옮기지는 않는다.
- 대신 상자 UI 안에 새 `DummyLootGridView`를 만들고, 기존 플레이어 인벤토리 `GridInventoryModel`을 공유하는 두 번째 `GridInventoryController`를 붙인다.
- 그래서 상자 UI가 열려 있으면 같은 인벤토리 모델에 기존 인벤 컨트롤러와 상자 우측 더미 컨트롤러가 동시에 존재하고, 전역 드래그 하이라이트 계산에 둘 다 참여할 수 있다.
- 이 중복 컨트롤러 구조가 “없는 스왑 대상”, “엉뚱한 빨간 칸”, “잔상”의 가장 유력한 원인이다.

## Key Changes
- `GridInventoryController`에 활성 여부 검증을 추가한다.
  - `GridStorageView`가 실제 화면에 표시 중인지 확인하는 `IsHighlightTargetActive` 성격의 프로퍼티/API를 둔다.
  - 전역 하이라이트 순회에서 숨겨진 기존 인벤토리 뷰, 닫힌 상자 뷰, panel에서 떨어진 더미 뷰는 제외한다.
- 상자 우측 인벤 더미 컨트롤러가 열려 있을 때는 기존 인벤 컨트롤러가 같은 모델로 하이라이트 계산에 참여하지 않게 한다.
  - 같은 `GridInventoryModel`을 가진 controller가 둘 이상이면, 현재 화면에 보이는 controller를 우선한다.
  - `sourceController`가 있으면 그 controller를 우선하고, 같은 모델의 숨은 controller는 skip한다.
- `GridInventoryController.Dispose()` 정리는 유지/보강한다.
  - 상자 닫기 시 dummy loot/player controller를 `activeControllers`에서 제거한다.
  - 이벤트 구독 해제와 slot color reset을 보장한다.
- target item 검증은 “모델에 있는가”가 아니라 “현재 활성 view에 실제로 렌더링되어 있는가” 기준으로 한다.
  - 실제 대상이 있는 경우 실패 스왑 위치 표시 유지
  - 모델만 있고 화면에 없는 대상은 스왑 후보에서 제외

## Test Plan
- 상자 UI가 열린 상태에서 상자 내부 드래그 시 기존 숨은 인벤토리 컨트롤러가 하이라이트에 끼어들지 않는지 확인한다.
- 상자 우측 인벤 드래그 시 상자 안 더미 인벤 컨트롤러만 기준이 되는지 확인한다.
- 빈칸 위 드래그에서 엉뚱한 빨간 칸이 뜨지 않는지 확인한다.
- 실제 다른 아이템 위 드래그에서는 실패 스왑 위치가 정상 표시되는지 확인한다.
- 상자를 닫았다 다시 열어도 이전 더미 컨트롤러 하이라이트가 남지 않는지 확인한다.
- `dotnet build Assembly-CSharp.csproj`로 컴파일 오류가 없는지 확인한다.

## Assumptions
- 상자 UI가 열려 있을 때 플레이어 인벤토리의 대표 view/controller는 상자 우측 더미 인벤이다.
- 기존 인벤토리 view가 숨겨져 있다면 전역 하이라이트 계산에서 제외해야 한다.
